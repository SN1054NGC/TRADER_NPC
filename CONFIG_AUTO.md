# CONFIG_AUTO — самосбор ассортимента из types.xml (план реализации)

Задача: сервер **сам** собирает товарный конфиг торговцев из `mpmissions/.../db/types.xml`
(цены уже считает `TraderAutoPrices`), не требуя ручной проводки `<OpenFile>`, но ручной конфиг
остаётся рабочим — его можно править и дописывать, и он имеет приоритет.

## Как устроено сейчас (проверено по коду)

* `missionServer.LoadServerConfigs()` (стр. 70-98): `SpawnTraderNpcObjects()` → `readTraderNpcVariables()`
  → `readTraderData()` → `readTraderNpcAdmins()` → `TraderAutoPrices.Run(m_Trader_ItemsClassnames)`.
* `readTraderData()` идёт двумя проходами по `TraderNpcConfig.txt`:
  1. **проход 1** (стр. 923-1010) — валюта, `<Trader>`-имена и `<Category>` (массив `m_Trader_Categorys` +
     `m_Trader_CategorysTraderKey`), `<OpenFile>` переключает файл;
  2. **проход 2** (стр. 1016-1161) — строки товаров; `traderID`/`categoryId` считаются **по порядку**
     встреченных `<Trader>`/`<Category>`, поэтому структура маркеров обязана совпадать в обоих проходах.
* Товары просто дописываются в `m_Trader_Items*` (стр. 1144-1156) — **дедупликации нет**.
* `TraderAutoPrices` уже генерирует `TraderNpcConfig_auto.txt` и **исключает классы, которые есть в ручном
  конфиге** (в шапке файла: «types 2255, generated 591, skipped 1488»), но пишет плоские строки
  товаров и требует, чтобы владелец сам вставил `<OpenFile>` под нужный `<Trader>/<Category>`.

## Решение (вариант A: слияние в коде, файл — только для просмотра)

1. `TraderAutoPrices.Run()` дополнительно возвращает посчитанные записи (товар, кол-во, buy, sell, ammo,
   категория) — параллельные массивы или `ref array<ref TraderAutoPricesEntry>`.
2. `nissionServer` после прохода 2 **дописывает** их в `m_Trader_Items*`, создавая один служебный раздел:
   `m_Trader_TraderNames.Insert("Auto Trader")`, `m_Trader_Categorys.Insert(<тип>)` +
   `m_Trader_CategorysTraderKey.Insert(<индекс>)` — строго **до** отправки данных клиенту
   (RPC-пакеты формируются в том же `readTraderData`, стр. ~400-460).
3. Файл `TraderNpcConfig_auto.txt` продолжает писаться, но как **справочник** (шапка: «применяется
   автоматически, файл нужен для просмотра и копирования цен»). Никаких `<OpenFile>` — значит нет
   двойного добавления.
4. Приоритет и защита: генератор исключает классы из ручного конфига; при дописывании ещё раз
   проверяем, что классназвания нет в `m_Trader_ItemsClassnames` (страховка от дублей).
5. Переключатели в `TraderNpcVariables.txt`: `<FeatureAutoPrices> yes|no` (уже есть) и новый
   `<AutoPricesApply> yes|no` — «применять автоматически» (по умолчанию yes) vs «только файл-справочник».
6. Категории авто-раздела: по типу предмета (оружие / патроны / магазины / еда / медицина / одежда /
   инструменты / прочее) — классификация уже есть внутри `TraderAutoPrices`.

## Что останется от старого ручного конфига

* `TraderNpcConfig.txt` остаётся главным файлом: валюта, `<Trader>`/`<Category>` для «своих» торговцев,
  ручные цены, `<SellCoef>`, ручные товары с явными ценами.
* Авто-раздел добавляется *рядом* (отдельный торговец «Auto Trader»), ничего в ручном файле не
  перезаписывает — «менять и дописывать» работает как раньше.
* Полностью автоматический режим: если ручной `TraderNpcConfig.txt` пуст (только валюта), сервер всё
  равно поднимет ассортимент из `types.xml`.

## Порядок работ

- [ ] 1. `TraderAutoPrices`: вернуть записи наружу + группировка по категориям.
- [ ] 2. `missionServer`: авто-раздел + дедупликация + `<AutoPricesApply>`.
- [ ] 3. Шапка сгенерированного файла: «справочник, применяется автоматически».
- [ ] 4. Проверка: `check_compile` + лог (кол-во применённых позиций, отсутствие дублей, торговцы = OK).
- [ ] 5. Проверка в игре: у торговца «Auto Trader» видны категории, цены совпадают с файлом.
