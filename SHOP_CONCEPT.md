# КОНЦЕПЦИЯ: ПОКУПКА КОИНОВ ЧЕРЕЗ САЙТ (черновик для обсуждения)

Статус: обсуждается. На первом этапе — **виртуальный магазин** (без реальных денег), чтобы отладить всю цепочку.

## 1. ИДЕЯ В ОДНОМ АБЗАЦЕ

В окне торговца появляется кнопка «Купить коины». Игрок нажимает — открывается браузер на странице магазина
с его SteamID. Он оформляет покупку (на тестах — «виртуальная оплата»), сайт пишет транзакцию в свою базу.
Игровой сервер раз в 30-60 секунд опрашивает API сайта и начисляет коины на аккаунт игрока; игрок видит их
в окне торговца. Сайт хранит и то, что у игрока было, и то, что куплено (журнал транзакций), сервер —
локальный кэш баланса, чтобы покупка не потерялась при падении сайта или сервера.

## 2. ПОЧЕМУ ИМЕННО ТАК (что позволяет движок)

| Возможность | Статус | Где |
|---|---|---|
| Открыть браузер из игры | **есть** | `proto native void OpenURL(string url)` — `dta/scripts/3_Game/Global/Game.c:1377`; ваниль так открывает форум/отчёт из меню |
| HTTP-запросы с сервера | **есть** | `RestApi`/`RestContext` — `dta/scripts/3_Game/Http/RestApi.c`: `GET(cb, path)`, `POST(cb, path, data)`, `FILE(cb, path, file)`, `GET_now` (блокирующий, не использовать) |
| Асинхронный ответ | **есть** | `class RestCallback { OnSuccess(data, size); OnError(code); OnTimeout(); }` |
| Идентификация игрока | **есть** | `player.GetIdentity().GetPlainId()` — SteamID64; у нас уже используется (`m_Trader_PlayerUID`) |
| Постоянное хранилище на сервере | **есть** | файлы в профиле (`OpenFile`, `FileReadHelper`) — как `TraderConfig.txt`; есть готовый логгер плагина |
| Периодический опрос | **есть** | `Timer` + `PluginBase` (у нас `PluginTraderServerLog` как образец) |
| Сервер как HTTP-сервер | **нельзя** | сервер не может принимать запросы; поэтому опрос инициирует игра |

## 3. ПОТОК ПОКУПКИ (шаги)

1. Игрок в окне торговца жмёт `btn_coins`.
2. Клиент показывает окно `TraderShop`: ссылка вида `https://shop.example/?uid=<SteamID64>&code=<6 цифр>` и кнопка «Открыть магазин».
3. Кнопка вызывает `g_Game.OpenURL(url)` — открывается системный браузер (или Steam overlay).
4. Игрок авторизуется на сайте (Steam OpenID, либо ввод кода `code` — тогда сервер должен знать этот код).
5. Выбирает товар, нажимает «Купить». В тестовом режиме — фейковый платёж (кнопка «оплатить виртуально»).
6. Сайт создаёт `purchases` (status=paid) и запись в `coin_ledger` (delta=+N коинов, delivered=0).
7. Сервер игры (плагин) раз в 30-60 с делает `GET /api/v1/ledger?after_id=<lastId>&limit=100`.
8. Сервер применяет начисления к аккаунтам (по SteamID), обновляет локальный файл, отвечает `POST /api/v1/ack {ids:[...]}`.
9. Клиенту уходит RPC: обновить счётчик коинов + уведомление «Получено 500 коинов».

Почему ack, а не просто `after_id`: если игровой сервер потеряет свой файл, он запросит всё заново и
начислит повторно. С ack сайт помечает строки как выданные и повторная выдача невозможна.

## 4. МОДЕЛЬ ДАННЫХ САЙТА (черновик SQL)

    products(id, sku, title, coins, price_rub, price_usd, active, sort)
    players(steam_id PK, nickname, first_seen, last_seen, balance_coins, total_spent_rub)
    purchases(id, steam_id, sku, qty, amount, currency, provider, provider_tx, status, created_at, paid_at)
    coin_ledger(id AUTOINC PK, steam_id, delta, reason, purchase_id, created_at, delivered_at)
    game_servers(id, name, token, last_seen)
    admin_actions(id, admin, steam_id, delta, comment, created_at)

`players.balance_coins` — «то, что у игрока есть на сайте»; `coin_ledger` — «что куплено/начислено/списано».
Баланс всегда можно пересчитать из журнала (`SUM(delta)`) — это и есть гарантия, что ничего не потеряется.

## 5. ХРАНЕНИЕ В ИГРЕ

Файл `$profile:Trader/TraderAccounts.txt` (или `.json`), строка на игрока:

    SteamID64|nickname|coins|rubles|lastLedgerId|updatedAt

- `coins` — донат-валюта (не теряется при смерти, привязана к аккаунту, а не к персонажу);
- `rubles` — игровая валюта/предметы (как сейчас, лут и награды);
- `lastLedgerId` — докуда синхронизировано (плюс ack на сайте);
- админы могут править файл вручную — сервер перечитает (или через админ-команду).

Важно: сейчас деньги в моде — это ФИЗИЧЕСКИЕ купюры (`increasePlayerCurrency` создаёт предметы).
Коины так делать нельзя (их нельзя терять при смерти) → коины живут в файле аккаунта и синхронизируются клиенту как число.

## 6. ДВЕ ВАЛЮТЫ: РУБЛИ И КОИНЫ

| | Рубли | Коины |
|---|---|---|
| Источник | продажа лута, награда за зомби | покупка на сайте, награды от админа, ивенты |
| Хранение | предметы в инвентаре | аккаунт (файл/сайт по SteamID) |
| Теряются при смерти | да | нет |
| На что тратить | обычный ассортимент торговца, ремонт, услуги | эксклюзивные позиции, скидочные купоны, конвертация в рубли, косметика |

Обсуждаемо: (а) обмен 1 коин = N рублей с комиссией; (б) товары «только за коины»; (в) коины дают постоянную
скидку +X % (например, VIP-статус на N дней) — это у нас уже есть механикой скидки за выживание.

## 7. ИНТЕРФЕЙС В ИГРЕ

- Кнопка `btn_coins` в `MoneyPanel` окна `TraderMenu.layout` (рядом с балансом).
- Новый `TraderShop.layout` (по нашему документу `LAYOUT_UI_GUIDE.md`): баланс коинов, ссылка, код, кнопка «Открыть магазин», список товаров (только для чтения).
- Счётчик коинов синхронизируется нетвар-переменной (`RegisterNetSyncVariableInt`), как рейтинг.
- Уведомления — существующий `TraderMessage` + звук купюр.

## 8. БЕЗОПАСНОСТЬ

- Клиент не решает ничего: он только показывает окно и открывает ссылку. Начисление — только сервер.
- Ссылка содержит SteamID, но **не даёт прав**: покупка на сайте требует Steam-авторизации (OpenID) или одноразового кода.
- Платёж подтверждается вебхуком провайдера с подписью; в тестовом режиме провайдер фейковый.
- Ограничения: не более N коинов в сутки на игрока, лимит размера ответа, таймаут HTTP, ретраи с backoff.
- Логи: `PluginTraderServerLog` (сервер) + `PluginTraderTradesLog` (сделки) + новый `TraderShopLog` (начисления и ack).
- Не хранить платёжные данные на игровом сервере вообще: только id начисления и сумму.

## 9. ТЕСТОВЫЙ (ВИРТУАЛЬНЫЙ) РЕЖИМ

- `mode: test` в конфиге сайта → кнопка «Оплатить виртуально» вместо реального провайдера;
- «Виртуальный баланс» тестового игрока, сброс одной кнопкой в админке;
- админ-панель: выдать/снять коины по SteamID, посмотреть журнал, сбросить баланс;
- сервер игры с `-noshop real` не может потратить реальные деньги (ключ `<ShopMode> test|live>`).

## 10. ФАЗЫ

1. Каркас в игре: кнопка + окно + `OpenURL` + страница-заглушка; начисление вручную через файл аккаунта. (~3-4 ч)
2. Сайт с БД и админкой, виртуальные покупки, API `/ledger` + `/ack`. (~1 день)
3. Плагин сервера: опрос, применение, идемпотентность, RPC-обновление счётчика, логи. (~4-6 ч)
4. Интеграция реального платёжного провайдера (вебхуки, подпись, возвраты).
5. Аналитика: сколько куплено, сколько коинов в обороте, влияние на экономику (важно: коины не должны ломать баланс рублёй).

## 11. ЧТО НУЖНО ЗНАТЬ ОТ ВЛАДЕЛЬЦА

1. Стек сайта: PHP / Node.js / Python? Хостинг и домен есть?
2. БД: MySQL / PostgreSQL / SQLite? (для тестов хватит SQLite или даже JSON-файла)
3. Реальные платежи: какой провайдер (ЮKassa, Stripe, Tebex, Steam?) — Tebex/Steam удобнее всего для DayZ-серверов, но не для RU-карт.
4. Курс: сколько коинов за рубль и что можно купить за коины (обмен на рубли, эксклюзив, VIP-скидка?).
5. Список товаров и цены (SKU) — кто их ведёт, нужна ли админка.
6. Может ли игровой сервер в интернет (обычно да) и есть ли у него https-клиент (в DayZ 1.29 `RestApi` работает на сервере).
7. Нужен ли вход на сайт через Steam (OpenID) или хватит одноразового кода из игры.
